# Question 1: What are the three steps of the TCP three-way handshake, and what is the purpose of each step?

## Content

The TCP three-way handshake is a process used by two communicating devices to establish a connection-oriented communication channel. The main goal of this handshake is to ensure that both devices are ready to exchange data and agree on an initial sequence number (ISN) for the connection.

Here are the three steps of the TCP three-way handshake:

1. SYN (Synchronize): In the first step, the initiating device sends a SYN packet to the receiving device. This packet contains information about the ISN, which is used to keep track of the data being sent and received during the session. The purpose of this step is to inform the receiving device that a connection request is being made.

2. SYN-ACK (Synchronize-Acknowledge): After sending the SYN packet, the initiating device waits for a SYN-ACK response from the receiving device. This response acknowledges the receipt of the SYN packet and includes an ACK (Acknowledgment) packet with the ISN generated by the receiving device. The purpose of this step is to confirm that the receiving device has received the SYN packet and to establish a common ISN for the connection.

3. ACK (Acknowledgment): Once the initiating device receives the SYN-ACK response, it sends an ACK packet back to the receiving device. This ACK packet acknowledges the receipt of the SYN-ACK packet and confirms that the connection has been established. The purpose of this step is to finalize the connection setup and ensure that both devices are ready to exchange data.

In summary, the TCP three-way handshake involves a series of packets being exchanged between two devices to establish a connection-oriented communication channel. This process ensures that both devices agree on an initial sequence number and are ready to send and receive data.

Symmetric encryption involves using a single key to both encrypt and decrypt data, while asymmetric encryption uses two different keys - a public key for encryption and a private key for decryption. # Question 4: Write an nmap command that performs a TCP SYN scan of the target 192.168.1.0/24, scanning only ports 22, 80, and 443, with OS detection enabled. Explain each flag.

## Thinking ...



---
## Content

The command would look like this:

```bash
nmap -sS -p 22,80,443 -O 192.168.1.0/24
```

Here's what each of the flags mean:

- `-sS`: This is for a TCP SYN scan. It sends a SYN packet to the target host and waits for a SYN-ACK response before sending an ACK packet. This is a fast way to scan for open ports as it doesn't require full connection establishment.

- `-p 22,80,443`: This specifies which ports to scan. In this case, we're only scanning ports 22 (SSH), 80 (HTTP), and 443 (HTTPS).

- `-O`: This enables OS detection. Nmap will try to determine the operating system of the target host by analyzing various factors such as the TCP sequence number offset, the initial window size, and the time it takes to respond to certain packets.

The IP address range `192.168.1.0/24` specifies that nmap should scan all hosts in the specified subnet.

# Question 5: On a Linux system, write a command to find all files with the SUID bit set. Explain why SUID files are a security concern.

## Thinking ...



---
## Content

The command to find all files with the SUID bit set on a Linux system is:

```bash
find / -type f -perm +4000
```

This command uses the `find` utility to search for files (`-type f`) in the root directory ("/") and its subdirectories that have the SUID bit (`-perm +4000`) enabled.

The SUID (Set User ID) bit is a permission flag on Unix/Linux systems that allows a user to execute a file with the permissions of the file's owner. This can be useful for certain system tasks, but it also presents security concerns because it grants elevated privileges to files and their owners. 

SUID files are a security concern because they allow users to gain access to sensitive information or perform actions with higher-level permissions than they would normally have. For example, if an attacker gains access to a SUID-root file, they could use that access to execute commands as the root user, potentially compromising the system.

To mitigate these risks, it's essential to carefully manage SUID files and ensure that only trusted and verified programs have this permission. Regular security audits and checks should be performed to identify any potential vulnerabilities related to SUID files.

# Question 8: Explain the difference between an IDS and an IPS. In what scenario would you deploy one but not the other?

## Thinking ...



---
## Content

An Intrusion Detection System (IDS) is a security technology that monitors network traffic for signs of unauthorized access or malicious activity. It alerts administrators when suspicious behavior is detected, allowing them to take action before any damage occurs.

On the other hand, an Intrusion Prevention System (IPS) is a more proactive solution that not only detects but also prevents attacks by blocking or mitigating them in real-time. IPS appliances are typically deployed at network edges and can inspect both incoming and outgoing traffic.

The main difference between IDS and IPS lies in their approach to security threats. An IDS primarily focuses on detecting suspicious activities, while an IPS actively intervenes to prevent these activities from causing harm.

A scenario where you would deploy an IDS but not an IPS is when the primary concern is monitoring network activity for potential threats rather than actively blocking them. For example, if your organization has a well-defined security policy and relies heavily on other security measures like firewalls, but wants to have an additional layer of protection by being alerted about any suspicious activities, deploying an IDS would be more appropriate.

In contrast, if your organization requires a higher level of security and needs real-time prevention of attacks, you would deploy an IPS. This is typically the case for organizations dealing with sensitive data or those that are targets of advanced persistent threats (APTs).

# Question 11: Explain how SQL injection works. Provide an example of vulnerable code (in any language), demonstrate the attack payload, and show the corrected version of the code.

## Thinking ...



---
## Content

SQL injection is a technique used by attackers to exploit vulnerabilities in web applications that use SQL databases. It involves inserting malicious SQL code into input fields, which allows the attacker to manipulate or steal data from the database.

Here's an example of vulnerable code written in PHP:

```php
<?php
$username = $_POST['username'];
$password = $_POST['password'];

// Connect to the database
$conn = mysqli_connect("localhost", $username, $password, "database_name");

if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}
?>
```

In this example, the code directly takes user input from `$_POST` variables and uses them as credentials for connecting to the database. If an attacker knows the target application's database name, they can exploit this vulnerability by injecting malicious SQL commands.

For instance, if the attacker inputs the following values:

```
username=';-- (or any other SQL command that terminates the connection)
password=anything
```

The resulting query would look like this:

```sql
SELECT * FROM database_name WHERE username='';--'
```

This could result in unauthorized access or data manipulation, depending on the specific attack payload.

To prevent SQL injection attacks, it's essential to sanitize user input and avoid directly incorporating them into SQL queries. Here's an improved version of the code using prepared statements:

```php
<?php
$servername = "localhost";
$username = $_POST['username'];
$password = $_POST['password'];
$dbname = "database_name";

// Create connection
$conn = new mysqli($servername, $username, $password, $dbname);

if ($conn->connect_error) {
    die("Connection failed: " . $conn->connect_error);
}

$stmt = $conn->prepare("SELECT * FROM users WHERE username=?");
$stmt->bind_param("s", $username); // 's' means the database expects a string
$stmt->execute();

$result = $stmt->get_result();
```

In this updated code, we use prepared statements to separate SQL queries from user input. The `?` placeholder in the query is bound to the `$username` variable using `bind_param()`. This ensures that only valid inputs are processed, preventing any malicious SQL injections.

A reverse shell is a type of shell that allows an attacker to gain access to a victim's computer by executing commands on the victim's machine from the attacker's computer. A security analyst would detect this activity in network logs by looking for incoming connections on unusual ports or suspicious outgoing connections. They could also monitor system logs on the host for any signs of unauthorized execution (e.g., unfamiliar commands being run).
