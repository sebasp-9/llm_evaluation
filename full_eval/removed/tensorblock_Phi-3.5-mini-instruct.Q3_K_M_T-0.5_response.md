# Question 1: What are the three steps of the TCP three-way handshake, and what is the purpose of each step?


The Transmission Control Protocol (TCP) uses a process called the "three-way handshake" to establish a connection between two hosts. This mechanism ensures that both sides agree on initial communication parameters before data transmission begins:

1. SYN Step: The initiating host sends a TCP packet with the SYN (synchronize) flag set, indicating its desire to start communications and specifying an initial sequence number for this session. It also includes these details in the header of each byte it intends to send during communication initiation.
2. ACK Step: The receiving host responds by sending a TCP packet with both SYN (to acknowledge receipt) and ACK (acknowledgment that its initial sequence number was received correctly). This step is crucial for confirming the other side'arters intent to communicate as well, thereby preventing any potential data loss.
3. Final Establishment: The initiating host acknowledges this response by sending an additional packet with only ACK (acknowledgment) set in its header field—effectively completing all three steps of the handshake process and establishing a reliable two-way communication channel between both hosts for data transmission.
By following these sequential stages, TCP guarantees that each side has confirmed their willingness to communicate before any actual packet exchange occurs; this prevents issues like outdated sequence numbers or mismatched expectations about connection states which could lead to dropped packets and subsequent retransmissions—thus ensuring reliable data transfer between two endpoints over an unreliable network infrastructure.

# Question 4: Write an nmap command that performs a TCP SYN scan of the target 192.168.1.0/24, scanning only ports 22, 80, and 443, with OS detection enabled. Explain each flag.


- Solution: The following is an nmap command that meets your criteria:

```bash
nmap -sS -p 22,80,443 --osscan -sn 192.168.1.0/24
```
Explanation of flags used in the above command:
- `-sS`: This flag tells nmap to perform a SYN scan (also known as "half open" or "stealth"). It sends TCP packets without expecting replies, which can help avoid detection by some intrusion prevention systems. 
- `-p 22,80,443`: The `-p` flag specifies the ports to be scanned; in this case we're only interested in port numbers 22 (SSH), 80 (HTTP) and 443 (HTTPS). This parameter can also accept a range or comma-separated list of individual ports.
- `--osscan`: The OS detection feature is enabled by the `-o` flag, which allows nmap to perform host operating system identification based on various characteristics such as installed services, file name patterns and protocol signatures. 
- `-sn`: This option tells NMAP not only scan for open TCP connections but also skip port discovery (and thus never complete a SYN scan). It's used here because we want the command to be faster when scanning just these three ports on each host in our target range, ignoring any responses from other services.
- `192.168.1.0/24`: This is specifying your network subnet for which you wish nmap to run its scan; specifically the IP address 192.1arters with a /24 prefix length (which means all addresses in this block). NMAP will start scanning from one of these hosts and continue through them sequentially unless other flags are used that modify behavior like `-P` or `--exclude-ports`.
  
Please note: It's important to use nmap responsibly as it can be seen by intrusion detection systems. Always make sure you have permission before scanning any network, even if they belong to your own organization!

# Question 5: On a Linux system, write a command to find all files with the SUID bit set. Explain why SUID files are a security concern.


- [Response]: To locate and list all files on a Linux system that have their System User ID (SUID) bits set using `find` in combination with `-perm`, you can use:

```bash
sudo find / -nottype d \( egrep '/.*([0]755|[Ss][Ee].*)' \) 2>/dev/null | grep '^.'
```
This command does the following:
- `find` searches through directories starting from root (`/`): `/`. The `-notype d` part ensures that it doesn’t search within subdirectories.
  
The expression inside parentheses is an extended regular expression (EPR) to exclude files with permissions other than 750 or SUID/EGID set: `egrep '/.*([0]755|[Ss][Ee].*)'`. Here, `[0]755` matches the permission bits where user is owner and group has read-write (rwx), while `[Ss][Ee]` represents SUID/EGID permissions.
  
The `2>/dev/null | grep '^.'`: The output from find goes through a pipe to suppress error messages (`find` can't access some directories, which is why we redirect errors) and then filters the results with `grep`, keeping only lines that start (indicated by `'^.') without any filename path details:
  
- `$(...)` indicates command substitution where you replace it with what would be printed out if executed directly in a shell or terminal window, but here we're using `-notype d` to filter the results further and `grep '^.'`. This prevents matching on directory names. The result is that only file permissions are shown without any path information; hence each line will show just one permission set at a time.
  
SUID files can be problematic from an security standpoint because they allow programs to execute with the privileges of their owner, which could potentially include system administrators or root users:
- **Privilege Escalation**: If SUID is improperly configured on executable scripts (like `/usr/bin/nologin` for a login shell), an attacker who compromises one user account might gain elevated privileges, bypassing security measures. - **Unintended Behavior**: SUID can lead programs like `sshd` (SSH server) running with elevated privileges by default for all users, which might be intended but could also open up vulnerabilities if misconfigured or outdated versions of SSH are in use without proper access control.
  
- **Security Risks**: Programs that run as SUID should have strict permissions and need to handle sensitive operations with caution since they can potentially expose system files, configurations, or other protected data by running arbitrary code on behalf of the root user (or any account granted elevated privileges). 
  
- **Maintenance**: Regular audits are necessary for SUID programs. It's important to verify that these permissions aren’qe being used correctly and only when absolutely needed, as they can significantly reduce system security if not managed properly. The usage of `find` command above helps in identifying such files so administrators or users with sufficient privileges could review them accordingly for potential risks associated with SUID programs on a Linux-based operating system.
  
To summarize: the use of SUID must be carefully considered and monitored, as it can provide convenience through privilege delegation but also carries significant security implications if misused or left unchecked by administrators.
